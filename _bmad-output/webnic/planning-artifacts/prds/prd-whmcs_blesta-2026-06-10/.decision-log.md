# Decision Log — WebNIC Registrar Module PRD

Canonical memory + audit trail. Newest first.

## 2026-06-10 — Bootstrap (Update intent)

The PRD originated as a hand-authored research draft (`../research/research-prd-webnic-blesta-registrar.md`) with no decision log. This log was bootstrapped at formalization. The draft's own framing decisions, reverse-engineered:

- **D-001.** Release-section split: MVP = LogicBoxes parity; Section 2 = end-user value; Section 3 = reseller power. Each independently shippable, MVP-in-production assumed. *(Preserved.)*
- **D-002.** MVP is deliberately *un-novel* — mirror the proven LogicBoxes module to de-risk operator migration. *(Preserved.)*
- **D-003.** `cancelService` does **not** delete at registry by default (avoid irreversible loss); deletion gated behind explicit admin choice (FR26). *(Preserved; promoted from open question to stated decision — see C-006.)*
- **D-004.** Derive TLD rules dynamically from WebNIC extension-rule endpoints rather than hard-coding per-TLD requirements as LogicBoxes does (§4.5). *(Preserved as an intentional upgrade.)*

## 2026-06-10 — Formalization + 4 High validation fixes

Source of change: validation report `../research/webnic-prd-validation-2026-06-10/validation-report.md` (grade Fair, 4 High). Draft formalized into this canonical `prd.md` (`status: review`). The draft remains in `research/` as the input record.

- **C-001 (Finding 1 — parity-matrix framing).** Verified against `components/modules/logicboxes/logicboxes.php`: LogicBoxes overrides only a handful of registrar-contract methods and does its real register/transfer/renew work inside `addService`/`renewService` + the `tab*` methods; `registerDomain`/`transferDomain`/`getDomainContacts`/`lockDomain`/`sendEppEmail`/etc. are abstract-base defaults it never overrides. **Decision:** rewrote §6 with a "How LogicBoxes actually implements it" column + a ✅/🔁/⬆/🆕 legend, and reworded G1's success signal from a method-name inventory to an end-to-end behavioural test. The WebNIC module intentionally implements the modern domain-centric contract (an upgrade), wired into the service lifecycle.

- **C-002 (Finding 2 — forwarding/DNSSEC MVP regression).** Verified `getClientServiceTabs` ships `tabClientForwarder` unconditionally and `tabClientDnssec`/`tabClientDnsRecords` whenever `dns_management` is on (`config.json` sets it). Deferring forwarding+DNSSEC to Section 2 (FR45/FR46) while promising "0 regressions" (§12) was a contradiction. **Decision: pull URL/email forwarding + domain-level DNSSEC into the MVP** — new FR35a (forwarding) + FR35b (DNSSEC); §5/§6/§9 (`email_forwarding` flag) updated; §7.2 FR45/FR46 narrowed to advanced/zone-level remainder; §12 "0 regressions" now achievable. *Rationale:* this is the only option consistent with the PRD's own zero-regression parity thesis. **Reversible** — flag this scope call for user confirmation; alternative is to keep them in Section 2 and explicitly own the regression in §2.3/§12.

- **C-003 (Finding 3 — async subsystem under-specified).** Verified LogicBoxes is fully synchronous (no `cron()`, no pending table). **Decision:** named the async pending-order/transfer subsystem **net-new** (§4.2, §6 🆕 row); added WHAT-level FRs — FR39a (service state machine + required module-owned table), FR39b (poll cadence + backoff + hard give-up timeout + alert), FR39c (client-facing pending/failed state), FR39d (renew/cancel-while-pending policy). Give-up default tagged `[ASSUMPTION: 30 days]`, pending OTE confirmation (B5). §9 module-owned tables made required (not "if needed").

- **C-004 (Finding 4 — idempotency / lost-response recovery).** **Decision:** strengthened FR18 (distinct "duplicate registration" vs "duplicate charge" tracking) and added **FR18a** — durable registration-intent record committed before the API call, by-domain reconciliation on retry, never blind-resubmit, reconcile-by-query on unknown results. NFR4 updated. New **Blocker B2**: confirm WebNIC supports by-domain pending-order lookup (FR18a depends on it; escalate to critical if absent).

- **C-005 (coupled cheap fixes).** NFR1 now treats EPP/auth codes + order IDs as secrets (validation Medium). §11 restructured into **Blockers (B1–B7)** vs **Deferrable (D1–D4)** — OQ4/OQ5/OQ6/OQ2 promoted to blockers; new B2/B7 added. §12 split into binding **MVP exit criteria** vs monitored **post-launch KPIs** (kills the "illustrative" Medium) + counter-metric added. §1.4 glossary: host/glue/child-NS unified as one concept. §4.3 marked `[Unverified]` and gated on B7. FR7/§4.4 now require Blesta `Currencies->convert` (validation H1 → deferred D1).

- **C-006 (numbering convention).** New FRs use letter suffixes (FR18a, FR35a, FR35b, FR39a–d) so all pre-existing IDs (FR1–FR59, NFR1–NFR14) and the validation report's references stay stable. No renumber.

- **C-007 (deferred scope).** Validation Medium/Low findings not entangled with the 4 Highs were **deferred as logged open items** (consolidated under §11 D4) per user instruction ("fix the 4 Highs, leave Mediums as logged open items"): Domain Manager contract/version verification, basic-vs-full DNS enumeration, suspend/cancel baseline confirmation, token-cache/single-flight strategy, registration-saga orphan cleanup, NFR6 latency budget, OTE-vs-prod divergence.
