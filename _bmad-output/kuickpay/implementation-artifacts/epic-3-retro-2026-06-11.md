## 2. What Went Well

- **The 3-layer adversarial review caught 100% of the production-breaking bugs the green suite missed.** Every fail-open / precision / constraint defect this epic was surfaced by Blind Hunter / Edge Case Hunter / Acceptance Auditor, not by the passing tests — see §3 Pattern #1. The human-in-the-loop escalations (3-1, 3-6, 3-7) routed exactly the decisions that should not be made silently. This is the load-bearing safety net of the whole project.
- **Fail-closed discipline held at the money boundary (3-5).** Two-layer idempotency — a `FOR UPDATE` row re-read guarded on `status='confirmed_unposted' AND blesta_transaction_id IS NULL`, plus a Blesta-layer `getByTransactionId()` verify-before-adopt that demands an `approved` + already-applied transaction before adoption. A two-layer `validPaidDate` gate (the `getPostable` query filters `date_paid IS NOT NULL` **and** `postVoucher()` rejects empty/`0000-00-00`/unparseable dates → `manual_review`/`missing_paid_date`). Audit-on-failure is written on a fresh statement **after** `rollBack()` so it survives the rollback and can't abort the batch.
- **One validation path, reused across three lifecycle states — not reimplemented.** Parser (3-2, evidence-internal, no DB) → validator (3-4, DB-aware mapping/dedup/staleness) → posting re-validation under lock (3-5). 3-5 reused `KuickPayEvidenceValidator` via a default-preserving `allowedStatuses` parameter rather than forking the rules — and added a regression test proving the old default still rejects `confirmed_unposted`.
- **Reuse-over-reinvent held for the bulk safety net (3-7).** A backward-compatible per-consumer `expected` map extension to `parseBulk`, additive schema, lock reuse (`reconcile_pending`) — all 9 "must-not-break" invariants passed. The late-payment check was deliberately placed in the **shared** validator so the bulk path inherits it for free.
- **A real prior-epic gap was actually closed.** The Epic 2 HIGH carry-forward — "confirmed evidence with a null paid date must not reach posting" — was enforced in 3-5 (`validPaidDate`) and then **extended to the bulk parser in 3-7** (`missing_paid_date`, which retroactively closed a 3-4 deferral). The single most important money-safety carry-forward was honored.
- **Verification-honesty discipline held in all 8 stories.** Every record disclosed the exact PHP version (8.3.31, not the 8.2 target), the exact `--bootstrap tests/bootstrap.php tests` command, the missing root `../tests`, and the un-run live smoke — never overstating coverage (NFR12). No story re-discovered the `-c build/phpunit.xml` bootstrap bug.
- **TDD red-then-green was visibly honored** (3-2 and 3-7 both recorded failing tests before implementation), and the deferred-work ledger kept its named-consumer-story discipline.

## 3. What Was Challenging (cross-story patterns)

- **Pattern #1 — The fake-vs-reality gap is Epic 3's signature failure mode.** Test doubles hid *production-breaking* bugs in **4 of 8 stories**, and in every case the green suite passed while the bug was live:
  - **3-2:** `parseInquiryFields()` mistook a purely numeric transaction reference for a split thousands-separated amount → could confirm a paid row with the wrong reference. Survived 88 tests because *every fixture used a non-numeric `KP-TXN-*` ref.* (All three review layers converged on it.)
  - **3-5 (the money mover):** `toMinorUnitsOrNull` rejected Blesta's real `decimal(12,4)` 4-decimal amount strings (`"1000.0000"`); the adopt-existing-transaction path would have routed **every real transaction to `manual_review` in production.** Tests passed *only because the fakes used 2-decimal strings.* AC9 double-allocation was also tested through a *stubbed* validator until review forced a real-validator integration test.
  - **3-7:** an append-only fake item repo that did not enforce `(run_id, voucher_id) UNIQUE` / `NOT NULL` hid **two** real bugs — a duplicate Consumer Number aborting the entire bulk run (and demoting a confirmed voucher), and a bulk confirm with no usable paid date sitting unpostable forever.
  - **3-8:** the verification story's *own* new safety tests passed **vacuously** — an empty sink stringifies to `"[]"` and clears every leak pattern, and the leak scan never drove the confirmed reconcile branch it was named to protect.
- **Pattern #2 — Zero live verification, 8 of 8 stories. The gate has now been skipped three epics running.** Epic 1 AI-1 → Epic 2 AI-1 → Epic 3: a live PHP 8.2 + Blesta/MySQL/SOAP path was never stood up. Worse, **Story 3-8 — explicitly reclassified by the Epic 2 retro as "the mandatory payment-safety verification gate that must run against a real stack, not stubs, to mean anything" — ran entirely on fixtures + DI fakes, on PHP 8.3.31, with that downgrade pre-declared in its own acceptance criteria.** The money-moving posting service (3-5) has never created a real Blesta transaction against a real DB; the requested `1.1.0→1.2.0` upgrade smoke-test has no execution record; `ext-soap` remains an unverified deploy dependency.
- **Pattern #3 — A spec can be followed exactly and still ship a defect (again).** 3-6's lost-payment clock race: `expirePending()` issued the spec-prescribed *unconditional* `edit(status='expired')`. The bug lived in the spec's **deferral** — it had consciously punted clock alignment and asserted the limbo "self-heals," a claim adversarial review proved **false** for the concurrent-overlap case (`getExpirable` on the DB clock vs `getReconcilable` on the PHP clock, distinct locks → concurrent → a confirmed paid result overwritten to `expired`, never posts). Routed as Israr's call (Option A: status-guarded `expire()`). This is the exact Epic 2 Pattern #3, recurring.
- **Pattern #4 — The `$this->gatewayConfig`-null-in-production footgun recurred.** Reading the resolved gateway config inside `persistEvidence()` returns `null` in production unless the run path writes it to the member first. This caused a **real bug in 3-6**, and was pre-empted in 3-7 *only because it was explicitly remembered* ("Config threading — do not skip — caused a bug in 3.6"). A footgun that depends on per-story memory is a structural gap.
- **Pattern #5 — The schema-concurrency residual rode through a third epic, unbuilt.** `context_key`/`active_context_key` exists nowhere in the plugin (verified). 3-5's runtime `FOR UPDATE` lock blocks double-allocation *at posting time*, but the schema-level guarantee that two concurrent **pending** vouchers can't mint on one invoice is still absent — the same HIGH deferral spanning 2-2 → 2-3 → 2-4 → 3-4 → 3-5.
- **Blesta framework footguns kept surfacing at each new layer** (none pre-documented — Epic 2 AI-6 footgun note still unwritten): no nested transactions / no `forUpdate()` builder (raw bound `SELECT … FOR UPDATE`); a self-transacting `create()` called inside an outer `begin()` would commit early and drop the lock; `Transactions->add()` returns `int|void` and an `addBefore` listener can veto the insert; `outcomeStatus()` returns the *current* state on success; `upgrade()`'s `>= 1.1.0` early-return would have made the new `post_confirmed` cron unreachable on exactly the live-upgrade path; the `FIELDS` allowlist silently drops un-listed columns; DB-clock vs PHP-clock divergence across selectors.

## 4. Key Insights

1. **Verification debt is now load-bearing under a shipped, money-moving path — across three epics — and the fakes have become a liability, not just a convenience.** In 4 of 8 stories the fakes were *more permissive than production* (2-dp vs Blesta's 4-dp; append-only vs `UNIQUE`/`NOT NULL`; non-numeric vs numeric refs). A fake that is looser than the database does not de-risk the code; it manufactures false green and *delays* the bug to production. The adversarial review is doing heroic work standing in for a runtime — but the bugs it catches are precisely the fake-vs-reality gaps a live DB would catch for free, and the bugs it might miss are the runtime paths nobody can drive.
2. **An honestly-reported un-run gate is still an un-run gate.** 3-8 satisfied NFR12/AC2 perfectly — it disclosed PHP 8.3-vs-8.2, the missing `../tests`, and the un-run DB/SOAP smoke. But it was chartered to *run against the real stack*, and by its own ACs it did not. Honesty about the downgrade does not deliver the verification the downgrade skipped.
3. **The design discipline is genuinely strong; the entire gap is runtime, not design.** Fail-closed boundaries, single-owner posting, layered validation, two-layer idempotency, an honest ledger — all held. Nothing in Epic 3 suggests a design rethink. Everything in Epic 3 says the same thing the last two retros said: build the live path.
4. **A well-documented HIGH deferral can outlive the discipline that documents it.** The schema-concurrency story is perfectly traced and perfectly unbuilt for the third epic. The ledger is excellent at *describing* the gap and powerless to *close* it; only a written story does that.
