## 2. What Went Well

- **Deferral-closure was the strongest of any epic — the ledger discipline finally paid off at scale.** Epic 4 closed **five** carried items the ledger had explicitly pointed here: 4-4 resolved both 3-7 deferrals (the bulk run-summary **count model** — inclusive Manual Review with an indented Unmatched subset, Failed/Errors side-by-side and **never summed**, all truthful to stored counters with **no arithmetic in the view** — and the **`run_date` upper bound**, now a keyed three-way error contract bounded to ≤ today / ≥ −365d); 4-5 closed both audit-event deferrals (`voucher.generation_failed` from 2-2 `:75`, `evidence.error` from 3-3 `:83`) **and** propagated a non-empty `redacted_trace_id` onto posting audit events. This directly answers Epic 3's lament that "the ledger is excellent at *describing* a gap and powerless to *close* it."
- **A three-epic-old vacuous test was made real.** 4-5 root-caused the chronic `KuickPaySecretLeakageTest` baseline red to a **test-fixture contract violation** (a confirmed-capture voucher carrying two identities when a single inquiry echoes one), fixed it at the test layer only (no parser/validator change), and the leak scan's persisted-payload assertions jumped **~154 → 304** — i.e. the forbidden-pattern loop now executes for real instead of clearing vacuously. This is the exact "fakes must be at least as strict as production / a green test must not be vacuous" agreement from Epic 3, honored.
- **Review-finding severity dropped sharply, and 4-5 shipped with zero patches.** Epic 3 had production-breaking *money* bugs in 4 of 8 stories; Epic 4's findings were UI/ACL correctness — AJAX widget rendering, pagination state, output escaping, a diagnostics-gate wildcard bypass, a Check Now outcome-label, GET-only guards, an order-field allowlist. The single mutation story (4-3) needed exactly **one** patch; the logging story (4-5) needed **none** (13 review findings dismissed as non-actionable, 2 deferred LOW).
- **The first admin mutation surface was built fail-closed and ACL-correct by design.** 4-3's `ALLOWED_ACTIONS_BY_STATE` / `ALLOWED_FROM_BY_ACTION` maps, the requirement that the permission-action token **equal the controller method name** (so the framework route-gate default-denies), and Cancel being forbidden from `confirmed_unposted`/`posted` (real paid evidence cannot be deleted through cancel) all held. The diagnostics gate (4-2) was corrected to an **exact-action** ACL check that ignores the `'*'` wildcard — the highest-severity finding of the epic, caught by review.
- **Defense-in-depth company-scoping became the norm.** 4-1 promoted `company_id` from an optional filter (which leaked every company's vouchers if omitted) to a **mandatory, unconditional** first parameter; 4-4 handled the `kuickpay_reconciliation_items` table having **no `company_id`** with a two-layer guard (controller fetches the run via `getForCompany()` first, **and** the model method re-JOINs and filters server-side so it is safe on its own).
- **Single redaction boundary + choke-point logging.** 4-5 routed every SOAP outcome — success and **all** failure branches including the WSDL early-return — through one `outcome()` choke point, and built `response_summary`/`fault` from **safe tokens**, never from a redacted envelope string (which still carries `Envelope|Header|Body|*Result` tags the leak scan forbids). Every log/audit value originates from `KuickPayRedactor` output or a known-safe token.
- **Verification-honesty discipline held in all 5 stories** (NFR12, fourth epic): every record disclosed PHP 8.3.31-vs-8.2, the exact `--bootstrap tests/bootstrap.php tests` command, and named precisely what could not run (live `$this->log()` write, live ACL two-group separation, CSRF token validation, `.pdt` render, DB-backed upgrade smoke). None re-discovered the `-c build/phpunit.xml` bootstrap bug.

## 3. What Was Challenging (cross-story patterns)

- **Pattern #1 — The live-verification gate was formally promoted to a HARD precondition for exactly these stories, and then crossed without being met.** Epic 3's retro §7/§11 named the live path "a hard gate… **before Epic 4's admin-mutation stories (4-3/4-4) merge**," with the only alternative being "a written, signed risk-acceptance enumerating exactly what ships unverified." **Neither happened.** 4-3 (the project's first admin write surface, and the in-request trigger to the money-moving posting service) and 4-4 merged on `php -l` + component PHPUnit with fakes, on PHP 8.3.31. The admin HTTP layer — controllers, the live ACL gate, CSRF tokens, plugin-upgrade permission re-sync, `.pdt` render — has **zero executable coverage in this checkout**. The day a real admin clicks **Check Now** on a live stack is still the first time that code will execute. This is the **fourth consecutive epic** the gate was named first and skipped — and the first time it was skipped *after being elevated to a hard gate*, without the signed risk-acceptance fallback being exercised.
- **Pattern #2 — Adversarial review is still load-bearing; only the bug *profile* changed.** The mechanism that produced Epic 3's bugs is unchanged: integration code that touches `Record`, ACL, CSRF, and views cannot be unit-tested here, so it is verified by **reading, not running** — and review caught the integration bugs accordingly (4-1's AJAX widget render and pagination reset; 4-2's diagnostics ACL wildcard bypass and six null/`json_encode` TypeErrors; 4-3's Check Now mislabel; 4-4's GET-only and order-allowlist gaps). The green suite passed in every case while the bug was live. Severity fell because the surface moved off the money path — but the untested surface this epic (the admin HTTP/ACL/CSRF layer) is brand new and entirely review-covered.
- **Pattern #3 — The framework-footgun rediscovery tax is now visible and compounding.** With no "Blesta footguns" dev note (Action Item open since Epic 1), **every** Epic 4 story paid to re-learn framework traps: models don't auto-load for plugin controllers; `clients.id_code` is a computed `REPLACE(...)` expression, not a column; `amount` is `varchar` so range filters compare **lexicographically** (`"9" > "100"`); `Widget::setFilters()` is type-hinted `InputFields`, not array (a plain array is a fatal `TypeError`); `PluginManager::upgrade()` **deletes the entire permission/action set** on a version bump and re-adds only what `getPermissions()`/`getActions()` return; `Record->fetch()` returns `stdClass`; views auto-resolve as `<controller_snake>_<action>.pdt`; `Permissions::authorized()` short-circuits only when *no* permission row exists, so a `'*'` row makes specific actions fall through to default-deny; language files auto-load only the controller's own file; `kuickpay_reconciliation_items` has no `company_id`; `kuickpay_audit_events` is not indexed on `run_id`; `redactedDiagnosticText()` blanks values but **keeps** structural `Envelope|*Result` tags. The doc would have pre-empted at least half of these. It is now **four epics overdue and materially larger.**
- **Pattern #4 — Company-scoping is the single most-repeated finding across all four epics, and it recurred again.** It was caught and fixed every time (4-1 optional-filter leak → mandatory param; 4-4 items-table no-`company_id` → two-layer defense), but it keeps recurring because there is **no structural enforcement** — no base scoped-query helper that always applies `company_id`. A correctness property carried by per-story vigilance recurs by construction.
- **Pattern #5 — The first mutation surface introduced a real concurrency residual the engine can't yet prevent.** 4-3's manual **Check Now** deliberately skips the `reconcile_pending` batch lock (so it won't block on the 5-minute cron). That exposes the shared `persistEvidence()`'s **un-status-guarded terminal `edit()` (`KuickPayReconcileService.php:435`)**: if the cron confirms a voucher (`pending → confirmed_unposted`, writes `date_paid`) *while* a manual inquiry is in flight, the manual call's stale-guard sets `manual_review` and `:435` **overwrites the cron's confirmed-paid row**, demoting it to a stuck `manual_review` with a dangling `date_paid`. It is **safe** (fails closed, evidence preserved, NFR9 honored) but an operational regression; 4-3 closes the common case with a pre-inquiry fresh-status short-circuit and **accepts the during-inquiry interleave as a documented residual**. The fix (`WHERE status IN ('pending','retry')`) lives in shared Epic-3 code, out of 4-3 scope.
- **Pattern #6 — The schema-concurrency residual rode through a fourth epic, unbuilt.** `context_key`/`active_context_key` still exists nowhere. Epic 4 did **not** un-gate `replace`/concurrent issuance, so the gate this fix protects was not breached — but the story still does not exist, and Epic 5 is the last planned epic to write it.

## 4. Key Insights

1. **The hard gate was crossed without being met *and* without the escape valve.** Epic 3 offered two acceptable ways past the live-verification gate for 4-3/4-4: run the live path, or have Israr sign a written risk-acceptance. Epic 4 did neither — it merged the admin write surfaces on fakes and disclosed the gap honestly. Disclosure held; the gate did not; and production-enablement risk is now **implicit and unowned** rather than either eliminated or formally accepted. An honestly-reported un-run gate is still un-run — and a hard gate quietly crossed is worse than a soft one, because the team already agreed it mattered.
2. **Epic 4 is simultaneously the best-behaved epic on deferral-closure and the worst-positioned on runtime debt — and that is one fact, not two.** The cheap, in-scope, code-only items (counts, audit events, the vacuous test) got closed reliably; the items needing infrastructure (a live stack), a net-new story (schema concurrency), or a written artifact (the footgun doc) were skipped for the fourth time. The team dependably does what fits inside a story and dependably defers what doesn't. The same shape as Epic 2 and Epic 3 — one epic deeper, and now against the last-epic wall.
3. **Falling review-severity is a property of the *surface*, not evidence the runtime gap closed.** 4-5's zero patches and the epic's UI-grade findings are encouraging, but they reflect that the work moved onto Epic 3's already-reviewed engine (read + admin UI, "low new-engine risk" as the Epic 3 retro predicted). The mechanism that will surface the *next* production-breaking bug — integration code that has never executed — is fully intact under the new admin HTTP/ACL/CSRF layer.
4. **Three recurring classes — footgun rediscovery, company-scoping, and the schema residual — are all the same lesson: a discipline carried in per-story memory and adversarial review is not a structural guarantee.** A base scoped-query helper, a written footgun note, and a schema unique key each convert a property the team must *remember* into one the system *enforces*. Memory and review scale sub-linearly across epics; structure scales flat. Four epics in, the un-structured properties are exactly the ones still recurring.
