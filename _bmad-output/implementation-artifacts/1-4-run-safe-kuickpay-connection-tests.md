# Story 1.4: Run Safe KuickPay Connection Tests

Status: in-progress

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an admin operator,
I want to test KuickPay connectivity without accidentally creating a payable Voucher,
so that setup can be verified safely before customer use.

## Acceptance Criteria

(Reproduced verbatim from [Source: epics.md#Story 1.4, lines 373-393].)

**AC1 — Normal connection test reports outcome and creates no payment**
**Given** an admin runs the normal connection test
**When** the gateway contacts KuickPay
**Then** the test reports success, credential failure, endpoint unavailable, or timeout
**And** it does not create a payable Voucher or mark any invoice paid.

**AC2 — Prefer a safe metadata operation over InsertVoucher**
**Given** KuickPay supports a safe metadata operation such as `Echo` or `GetInstitutionsList`
**When** connection testing is configured
**Then** the gateway prefers that operation over `InsertVoucher`.

**AC3 — Live voucher test requires explicit confirmation and clear labeling**
**Given** an admin requests a live voucher test
**When** the action is submitted
**Then** explicit admin confirmation is required
**And** any resulting test record is clearly labeled as a test.

> **What this story actually changes** (read before scoping): Stories 1.1–1.3 delivered the gateway scaffold, the grouped settings form (incl. `wsdl_url` and `soap_timeout`), credential encryption/masking, and the gateway-owned `maskCredentials()` redaction boundary. Story 3.1 (now **done**) delivered the `lib/KuickPaySoapClient.php` SOAP wrapper plus `getSoapClient()`/`setMeta()` on the gateway. **1.4's net new work is a safe, in-scope connection test:** (1) add a sentinel-gated **"Test connection"** action to the settings form (Task 1); (2) implement a **transport-level HTTPS reachability probe** to the configured `wsdl_url` that reports **reachable / endpoint-unavailable / timeout**, creates no Voucher, makes **no SOAP operation call** and does **not** route through `getSoapClient()` (Task 2 — AC1 safe-path, AC2 "no InsertVoucher"); (3) add a **userinfo/SSRF guard** on the URL it fetches (Task 3); (4) add the language strings for the action and result states (Task 4); (5) **document the deferred contracts** — the real `Echo`/`GetInstitutionsList` safe-op test, server-side *credential-failure* validation, and the AC3 live-voucher test — and route them to their now-concrete owners (Task 5). **Scope decision (carried from product-owner decision 2026-06-09, re-validated after 3.1 landed — see Open Question #1):** ship the safe transport test now in Epic 1; defer the live SOAP safe-op test to **Story 5-1** and AC3 to **Epic 3**. See **Dev Notes → "Scope: what 1.4 owns vs what later stories own"** and **"Why a transport probe, not a SOAP call — even though the SOAP client now exists."**

## Non-Negotiables (read before any task)

1. **The connection test must never create a Voucher or mark any invoice paid.** [Source: epics.md AC1 line 384; prd.md FR-4 lines 117-124; UX-DR10] The 1.4 probe makes **no SOAP operation call at all** — it performs a transport-level HTTPS reachability request to `wsdl_url` only. It must **not** call `InsertVoucher`, `BillPaymentInquiry`, `BillPaymentBulkInquiry`, `Echo`, `GetInstitutionsList`, or any business/SOAP operation; it must not write to any voucher/invoice/transaction table; it must not touch `buildProcess`/`validate`/`success`. AC2's "prefer a safe metadata operation over `InsertVoucher`" is satisfied because the probe creates nothing and calls no business op.

2. **Do NOT call `$this->log()` from inside `editSettings()`.** [Source: components/gateways/lib/gateway.php:254-288; app/models/logs.php:132-176; app/models/gateway_manager.php:599-650] During `editSettings()` the gateway instance has **no `gateway_id`** (`GatewayManager::edit()` loads a fresh `loadGateway()` instance and never calls `setGatewayId()`), and `Logs::addGateway` **requires** a valid `gateway_id` (`validateExists` against `gateways`, **no `if_set`**). `log()` writes `gateway_id => $this->gateway_id` (null) and **throws** when `Logs->errors()` is non-empty (gateway.php:283-285) — so a `log()` call in the test path **would break the settings save**. The test reports **only** through `Input->setErrors()` (admin UI). (Story 3.1 Dev Notes line 161 re-confirms this exact constraint.)

3. **No raw transport/SOAP/exception detail in any admin-facing message.** [Source: epics.md UX-DR28; UX-DR7; ux EXPERIENCE.md] Every result message is a `$lang['Kuickpay.*']` key surfaced via `Input->setErrors()`. Never concatenate a cURL/`SoapFault`/exception string, a URL, a host, an operation name, a stack trace, or any credential into the message. Classify the failure **internally** to a state, then show the matching language-keyed string.

4. **Do NOT route the test through the SOAP client; make no SOAP call; add no `lib/` files.** [Source: 3-1 story lines 99,161 "Do NOT wire these into the Story 1.4 connection test (1.4 uses a cURL WSDL reachability probe)"; architecture.md:390-392 (Echo/GetInstitutionsList are **Optional**); addendum.md:17-18 ("if credentials permit"); composer.json (no `ext-soap`)] Story 3.1's `KuickPaySoapClient` now exposes `echoTest()` and `getInstitutionsList()` "for future setup checks" — but 1.4 must **not** call `getSoapClient()`, `echoTest()`, `getInstitutionsList()`, or instantiate `SoapClient`. Reasons: (a) 3.1 explicitly scoped those out of 1.4; (b) **`ext-soap` is not a declared dependency** (root `composer.json` requires `ext-curl` + `ext-openssl`; the gateway-local `composer.json` adds none) so a SOAP-based Epic-1 test could fail where the extension is absent, whereas **`ext-curl` is guaranteed present**; (c) `echoTest()`/`getInstitutionsList()` send **no credentials** (they bypass `withCredentials()`), so they add nothing over reachability for AC1's credential-failure state; (d) the `Echo`/`GetInstitutionsList` signatures are **unconfirmed** until Phase 0 finishes. The live safe-op SOAP test is the **Story 5-1** (opt-in live/sandbox) upgrade — see Task 5. A transport reachability request (HTTPS GET of the WSDL document) is **not** a SOAP call and is in-scope.

5. **The test action must not be triggered on a normal Save, and its sentinel must never persist.** The probe runs **only** when an explicit "Test connection" control posts `run_connection_test === 'true'`. A normal Save (sentinel absent) must behave exactly as today — no network call. `run_connection_test` is a transient action flag: it must **not** be added to `$rules`, must **not** be returned in `$meta`, and must be `unset()` before `return $meta` so it never reaches `gateway_meta`.

6. **1.4 is the gateway-side consumer of `wsdl_url` over cURL — guard the fetch.** [Source: deferred-work.md "wsdl_url HTTPS validation is lenient (SSRF / userinfo)"; architecture.md:83,460; KuickPaySoapClient::hasUsableWsdlUrl() lines 336-351] Before fetching, **reject a `wsdl_url` that contains userinfo** (`https://user:pass@host/…`) so credentials embedded in the URL are never transmitted/logged, and re-confirm the HTTPS scheme. HTTPS is already enforced by the 1.2 save rule (kuickpay.php:136-150). Enforce TLS peer + host verification on the request. **Mirror the call-time guard 3.1 already implements in `KuickPaySoapClient::hasUsableWsdlUrl()`** (https-only + `PHP_URL_USER`/`PHP_URL_PASS` null), but implement it independently in the cURL path (1.4 does not go through the SOAP client). A full host-allowlist is **deferred** (real KuickPay hosts are unconfirmed until Phase 0 / Epic 5) — document it, do not invent host literals.

7. **All admin-facing strings come from language files.** [Source: project-context.md#Language-Specific Rules; epics.md UX-DR28] Every label, note, and result message is a `$lang['Kuickpay.*']` key via `$this->_(...)` / `Language::_(...)`. Preserve the file's single-quote / one-key-per-line style; do not reorder or rewrap existing keys.

8. **Stay in scope; no regressions.** Touch **only** the three production gateway files (`kuickpay.php`, `views/default/settings.pdt`, `language/en_us/kuickpay.php`) — plus, optionally, **one** new committed unit test under the existing `tests/` dir (Task 6.4). Preserve all 1.1–1.3 behavior and all 3.1 additions. Do **not** add: a SOAP client / `lib/` classes, the protocol-library redactor, an AJAX/controller route, customer-facing changes, plugin code, schema, cron, or core edits. No file under `plugins/kuickpay_reconcile/` changes; no change to `lib/*` or 3.1's tests. Match parent signatures; target **PHP 8.2** (no 8.3+ syntax). [Source: architecture.md:765-778; project-context.md]

### Why a transport probe, not a SOAP call — even though the SOAP client now exists

When this story was first drafted, `KuickPaySoapClient` did not exist, so the only choices were "inline a raw `SoapClient` (forbidden by architecture.md:770)" or "a cURL transport probe." **Story 3.1 has since landed the client**, exposing `echoTest()` → `Echo` and `getInstitutionsList()` → `GetInstitutionsList` "for future setup checks." It is tempting to call one of them now. We deliberately do **not**, for four concrete reasons:

1. **3.1 scoped it out of 1.4 by name.** [3-1 story lines 99, 161] "Do NOT wire these into the Story 1.4 connection test (1.4 uses a cURL WSDL reachability probe and is out of scope here)." The cross-story contract 3.1 was built and reviewed against assumes 1.4 stays a transport probe.
2. **`ext-soap` is not a declared dependency.** Root `composer.json` `require` lists `ext-curl` and `ext-openssl` — **not** `ext-soap`; the gateway-local `composer.json` adds no extensions. An Epic-1 connection test that depends on `ext-soap` could break in a production environment where the extension is absent; **`ext-curl` is guaranteed present.** (3.1's deferred-work note even flags that ext-soap was only *observed* present on the dev box at PHP 8.3, not confirmed for the 8.2 target.)
3. **The safe ops send no credentials, so they don't unlock AC1's credential-failure state.** `echoTest()`/`getInstitutionsList()` call `KuickPaySoapClient::call()` directly, bypassing `withCredentials()` (verified KuickPaySoapClient.php:100-114, 233-243). They prove reachability + that the operation exists — the same class of signal the cURL probe gives — without authenticating. Real credential validation needs a credentialed op, which is the Story-5-1 upgrade.
4. **The `Echo`/`GetInstitutionsList` signatures are unconfirmed.** PRD addendum (17-18) marks both "if credentials permit"; architecture (390-392) marks them "Optional"; Phase 0 has not pinned their request/response shape. Calling an unconfirmed op can fault against a perfectly reachable endpoint, muddying the test result.

A **transport-level HTTPS reachability request** for the WSDL document is **not** a SOAP operation call — it honors architecture.md:770, needs no `ext-soap`, and still "contacts KuickPay" enough to report **reachable / endpoint-unavailable / timeout**. The real safe-op preference and the credentialed states upgrade cleanly in Story 5-1 by reusing 3.1's client. [Source: architecture.md:390-392, 765-778; 3-1 story:99,161; composer.json; addendum.md:17-18]

### Connection-test mechanism — the only viable Blesta hook

A Blesta **nonmerchant gateway** exposes exactly two admin interaction points: `getSettings()` (GET render) and `editSettings()` (POST save). There is **no** built-in `testConnection`/`validateConnection`/tab/action hook (confirmed across `components/gateways/lib/gateway.php`, `nonmerchant_gateway.php`, and `app/controllers/admin_company_gateways.php` — `manage()` is the only settings handler, and on POST it calls `GatewayManager::edit()` → `editSettings()`; there is no route that dispatches to an arbitrary gateway method). Therefore the test must run **inside `editSettings()`**, triggered by a **sentinel** posted from a dedicated "Test connection" submit button so that **normal saves never incur a network call**. The only feedback channel from `editSettings()` is `Input->setErrors()` (which blocks that submission). [Source: components/gateways/lib/nonmerchant_gateway.php; app/controllers/admin_company_gateways.php:162-293; app/models/gateway_manager.php:599-650; re-confirmed by 3-1 story:161]

**Honest UX consequence (document, don't fight):** because the only channel is `setErrors()`, the test cleanly reports **failures** (form re-renders with the language-keyed reason; save blocked so the admin fixes config) and reports **success implicitly** (no error → settings save → standard "Gateway updated"). There is **no** clean "Connection OK ✓" banner from within `editSettings()`. A richer, on-demand test with an explicit success affordance and a logged result requires a dedicated admin route (a real `gateway_id` context) and is **out of scope** for this gateway-only story — see Open Question #2.

### editSettings change (AC1) — exact diff

Insert between the existing `validates()` (line 267) and `return $meta;` (line 269). Do **not** add `run_connection_test` to `$rules`.

```php
        $this->Input->setRules($rules);
        $this->Input->validates($meta);

        // AC1: run the safe transport connection test only when the admin explicitly
        // requests it and base validation passed. Never on a normal Save. The probe
        // reports via Input->setErrors() only; it must NOT call $this->log() here
        // (gateway_id is null during editSettings(), so log() would throw), it must
        // NOT route through getSoapClient()/echoTest() (no SOAP call — see Dev Notes),
        // and it creates no Voucher.
        if (!$this->Input->errors() && (($meta['run_connection_test'] ?? 'false') === 'true')) {
            $this->runConnectionTest($meta);
        }

        // The action flag is transient — never persist it to gateway_meta.
        unset($meta['run_connection_test']);

        return $meta;
```

`runConnectionTest(array $meta): void` is a new `private` method (place it near `maskCredentials()`, away from `getSoapClient()` to keep the SOAP and transport paths visually separate): validate-no-userinfo + https → cURL GET of `wsdl_url` with `soap_timeout`-derived timeouts and TLS verification on → map `curl_errno`/response code to a state → `setErrors` the matching language key on failure (nothing on success). (`unset()` on an absent `run_connection_test` is a safe no-op; no `isset()` guard needed.)

### State-mapping table (cURL → AC1 state → language key)

| cURL signal | AC1 state | Behavior |
|---|---|---|
| `curl_errno() === 0` and `CURLINFO_RESPONSE_CODE > 0` (endpoint answered, any HTTP status) | **success** | No error set; settings save proceeds |
| `curl_errno() === CURLE_OPERATION_TIMEDOUT` (28) | **timeout** | `setErrors(Kuickpay.!error.connection.timeout)` |
| `curl_errno()` ∈ { `CURLE_COULDNT_CONNECT` (7), `CURLE_COULDNT_RESOLVE_HOST` (6), `CURLE_SSL_*` (35/51/58/60…), other transport errnos } | **endpoint unavailable** | `setErrors(Kuickpay.!error.connection.unreachable)` |
| `wsdl_url` contains userinfo / non-https | **blocked (pre-request)** | `setErrors(Kuickpay.!error.connection.url_userinfo)`; no request issued |
| `curl_init`/`ext-curl` missing | **unavailable** | `setErrors(Kuickpay.!error.connection.unavailable)` |
| **credential failure** (server rejects creds) | **N/A in 1.4** | Requires an authenticated safe SOAP op — **deferred to Story 5-1 / Epic 3** (Task 5) |

Notes: classify timeout **before** generic transport errors. The `soap_timeout`-derived probe timeout is clamped to **[1, 120]s** (default 30) per Task 2.2 — a `soap_timeout=1` is honored (the fast Test 6.3 path) and any large value is capped at 120 so the admin Save cannot hang. "Reachable" deliberately means *the endpoint answered* — a 401/404/500 still proves connectivity; deeper validation (valid WSDL, valid credentials) needs the credentialed SOAP op. (Whether a 4xx/5xx *should* instead be surfaced as "endpoint unavailable" rather than "reachable" is a deliberate product judgment — see **Open Question #5**; this story keeps pure reachability so an auth-protected WSDL legitimately returning 401/403 is correctly treated as reachable.) Never surface the HTTP code or cURL message to the admin (Non-Negotiable #3).

## Open Questions / Clarifications (for the team — non-blocking for dev start)

1. **Now that Story 3.1 is done, should 1.4 use the real `Echo`/`GetInstitutionsList` SOAP op instead of the cURL probe?** This story keeps the cURL transport probe and defers the live safe-op test to **Story 5-1** — because `ext-soap` is not a declared dependency (root `composer.json` requires only `ext-curl`/`ext-openssl`), 3.1 explicitly scoped the safe ops out of 1.4, the safe ops send no credentials (so they don't unlock AC1's "credential failure"), and their signatures are unconfirmed until Phase 0. **Recommended:** keep 1.4 as the safe transport probe (ships in Epic 1, no `ext-soap` risk) and wire 3.1's `echoTest()`/`getInstitutionsList()` in Story 5-1 behind an opt-in + `ext-soap`/Phase-0 gate. If the team prefers to pull the live safe-op into 1.4 now, confirm `ext-soap` is guaranteed in production and add it to `composer.json`, and confirm the safe-op name/signature with KuickPay (Phase 0) first.
2. **On-demand test with an explicit success affordance + logged result.** Within the gateway-only, no-core-change constraint, the test runs inside `editSettings()` and can only report **failures** (via `Input->setErrors()`); a successful test is implicit (settings save), and it **cannot** write a gateway log entry (null `gateway_id` during edit). A richer affordance (explicit "Connection OK ✓", a logged result, re-test without re-saving) needs a dedicated admin route where a real `gateway_id` exists. **Recommended:** accept the save-time failure-reporting MVP now; build the on-demand logged test with admin tooling (Epic 4) or alongside Story 5-1.
3. **Server-side credential validation (AC1 "credential failure").** A transport probe cannot authenticate. **Recommended:** deliver this with the authenticated safe-op test (Story 5-1 / Epic 3) using 3.1's `KuickPaySoapClient`; confirm with KuickPay (Phase 0) the exact safe-op name + signature and whether it validates the voucher pair, the inquiry pair, or both.
4. **AC3 live-voucher test.** Deferred to Epic 3 (needs `InsertVoucher` + durable Voucher persistence + a test-label field). 1.4 guarantees no voucher can be created. Confirm the test-record label mechanism (an `is_test` flag on `kuickpay_vouchers`?) when Epic 2/3 define the schema.
5. **Should the transport probe treat HTTP 4xx/5xx as "endpoint unavailable" rather than "reachable"?** As designed, *any* answered HTTP status (including 404/500) counts as **reachable** — because the probe checks transport reachability, not WSDL validity, and an auth-protected WSDL legitimately returns **401/403** while still being correctly configured (the SOAP call carries the credentials). The trade-off: a mistyped WSDL **path** returning 404 would also pass the test. **Recommended:** keep pure reachability for 1.4 (an answered endpoint = connectivity proven; deeper endpoint-validity is the credentialed safe-op test in Story 5-1) and frame the UX copy as "endpoint reachable," not "endpoint valid." If the team wants stricter setup-time validation, decide which status classes count as failure (e.g. treat 5xx and 404 as unavailable but keep 401/403 as reachable) — but that is endpoint-validity, which belongs more naturally with the Story 5-1 safe-op test.
