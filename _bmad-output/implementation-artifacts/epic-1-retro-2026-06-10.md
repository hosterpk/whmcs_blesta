## 2. What Went Well

- **Repeatable testability pattern — pure-helper extraction.** `currencyEligible()` (1-5) and `protected maskCredentials()` (1-3) were extracted so they could be unit-tested without stubbing view/`Loader`/`PluginManager`. This was the single move that made every story verifiable given no live runtime.
- **Defense-in-depth over reinvention (1-5).** Recognized Blesta's native `gateway_currencies` inner-join already hides non-PKR currencies; layered a fail-closed `buildProcess()` guard on top rather than rebuilding the mechanism.
- **Sentinel-gated connection probe (1-4).** Nonmerchant gateways have no test hook; the team added a cURL reachability probe *inside* `editSettings()` that sends no credentials and creates no voucher. Normal saves incur no network call.
- **Security beyond spec (1-4).** SSRF private-range guard resolved live at the user's request — blocks loopback/RFC1918/link-local/reserved ranges incl. cloud metadata `169.254.169.254`, with `CURLOPT_RESOLVE` pinning to defeat DNS rebinding (+4 tests).
- **Honest UX copy under architectural constraint (1-3).** Where the gateway cannot distinguish GET from POST on a failed re-render, copy was rewritten to never claim "currently stored" — "hidden for security; re-enter to save any change" is true in both contexts.
- **Adversarial review discipline.** Every story passed a 3-layer review (Blind Hunter, Edge Case Hunter, Acceptance Auditor). High signal-to-noise: 9–12 findings dismissed as noise per story, near-zero escaped defects, all ACs + Non-Negotiables PASS.
- **Disciplined deferred-work ledger.** Every deferral records origin, file path, reason, and a revisit trigger. This is the epic's strongest durable artifact.

## 3. What Was Challenging (cross-story patterns)

- **Pattern #1 — No live runtime, 5 of 5 stories.** All verification was `php -l` + component PHPUnit + grep + structural parity. No story exercised a live Blesta admin, MySQL, or install/upgrade lifecycle. Compounding risk: `php -l` ran on **PHP 8.3.31** (no 8.2 binary available) while production is pinned to **PHP 8.2**; Story 3-1's record is internally contradictory about toolchain presence.
- **Pattern #2 — Blesta nonmerchant-gateway footguns, rediscovered repeatedly (1-2, 1-3, 1-4):**
  - `editSettings()` runs on an **id-less instance with null `gateway_id`** → cannot `log()` during a settings save; cannot keep-if-blank credentials.
  - `GatewayManager::setMeta` is **delete+insert** → no keep-if-blank for stored passwords.
  - **Checkbox render-default trap** — generic `fieldCheckbox` renders every box unchecked on first load, silently breaking `true`-default toggles.
  - **Button value brittleness** (sentinel vs label) and the **class-name camelCase round-trip** (`Kuickpay`, not `KuickPay`) for asset/view resolution.
  - None of these are written down where a future story author would find them.
- **Pattern #3 — The credential-masking baton passed three times and never landed.** Keep-if-blank deferred 1-2 → 1-3; found infeasible without a core change in 1-3; the `maskCredentials()` boundary expected its first caller in 1-4, but 1-4 sends no credentials → the boundary remains a contract, now pushed to Epic 3 / Story 5-1.
- **Boundaries shipped as contracts with no live caller.** Mask-allowlist completion, redactor value-based redaction, WSDL host-allowlist / userinfo rejection, numeric bounds/relational checks — all correct *today* only because nothing exercises them. **Epic 2/3 are the first callers.**

## 4. Key Insights

1. **Epic 1 was, by design, a "safe inert scaffold" epic** — its safety comes from having no live mutation surface, which is exactly why much hardening was legitimately deferred "to the first consumer."
2. **The deferral strategy is disciplined but creates a hand-off risk:** a deferred contract can get its first caller in Epic 2/3 without anyone re-reading the ledger. Deferrals must be tagged with the consumer story.
3. **Verification debt is the real accumulating risk, not feature debt.** Lint-on-8.3 + no-DB is acceptable for an inert scaffold; it is **not** acceptable for Epic 2's first schema (2-1) or first mutation surface (2-3).
