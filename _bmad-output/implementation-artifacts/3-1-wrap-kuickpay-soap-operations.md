# Story 3.1: Wrap KuickPay SOAP Operations

Status: in-progress

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a finance operator,
I want KuickPay SOAP calls isolated behind a safe client,
so that reconciliation and voucher issuance use configured, redacted, timeout-bound, TLS-validated provider communication and never let raw SOAP decide payment outcomes.

## Acceptance Criteria

Derived from Epic 3 Story 3.1 (epics.md:580-598), FR15, and the architecture API/ownership contracts. Each is independently testable.

1. **Single SOAP entry point.** All KuickPay SOAP operations — `InsertVoucher`, `BillPaymentInquiry`, `BillPaymentBulkInquiry` (and optional safe-setup `Echo`, `GetInstitutionsList`) — execute only through the new `KuickPaySoapClient` wrapper around PHP `SoapClient`. No controller, view, cron, posting/reconciliation service, or the gateway itself instantiates `SoapClient` or branches on raw SOAP/XML directly. [Source: epics.md:130-131; architecture.md:383-406,770-772]
2. **Configured timeouts.** The client applies a connection timeout and a read/socket timeout derived from the gateway `soap_timeout` setting (with a safe floor/default when unset). A slow or hung endpoint cannot block indefinitely. [Source: epics.md:53,593; FR15; NFR7]
3. **TLS validation.** The client enforces TLS peer + hostname verification (verify_peer + verify_peer_name) on both the WSDL fetch and the SOAP call, and rejects a `wsdl_url` containing embedded userinfo (`user:pass@`). [Source: epics.md:593 (TLS validation applied); 1-4 TLS-verification stance (`CURLOPT_SSL_VERIFYPEER`/`VERIFYHOST` → SoapClient `verify_peer`/`verify_peer_name`); 1-4 Non-Negotiable #6 (SSRF/userinfo guard)]
4. **Per-operation credential selection.** `InsertVoucher` uses voucher credentials (`voucher_username`/`voucher_password`); `BillPaymentInquiry`/`BillPaymentBulkInquiry` use inquiry credentials (`inquiry_username`/`inquiry_password`) **except** when `inquiry_same_as_voucher === 'true'`, in which case they fall back to voucher credentials. [Source: epics.md:593; kuickpay.php:125-130; 1-3 same-as-voucher dedupe contract]
5. **Sanitized logging / redaction boundary.** Every request and response value the client logs, summarizes, embeds in an exception/diagnostic, or returns as a diagnostic field passes through a redactor first. Credentials (`userName`/`password` and variants) and PII (`Name`, `Mobile`, `Email`, `Branch`, `InstitutionID`) never appear unmasked in any log line, exception message, transport outcome diagnostic field, or test output. The single exception is `raw_result` — the functional parser payload of AC7, which is never logged, displayed, or placed in a diagnostic and is therefore not a "diagnostic field" this AC governs (see AC7). [Source: epics.md:53,132; architecture.md:373,656; FR15,FR27,NFR8; docs/kuickpay/fixtures/redaction/credentials.xml]
6. **Structured transport outcome, never a payment decision.** On success, SOAP fault, transport failure, or timeout the client returns a single structured transport-outcome shape. A received response body — **including a SOAP `<Fault>` body** — is a transport *success*: `ok = true`, `error_class = null`, and the body is handed to the 3.2 parser via `raw_result`/`raw_envelope`. `error_class` is set to exactly one of `timeout` or `transport_error` (with `ok = false`) **only when no usable response body arrived**. `ok` reflects transport reachability only and is never itself a payment signal. The client never returns, infers, or stores a paid/not-paid/confirmed status and never emits the parser-owned error classes (`credential_error`, `malformed_response`, `unknown_status`, `amount_mismatch`, `duplicate_reference`, `unmatched_reference`) — a provider auth/credential rejection returned in a body is the parser's `credential_error` to make, not a `transport_error`. [Source: epics.md:595-598; architecture.md:569-579,648-661]
7. **Raw payload handed off for parsing only.** On a transport-successful call the outcome carries the raw provider response payload for the Story 3.2 parser to consume. Reading the operation-level result value off the `SoapClient` return — the `{Operation}Result` property, e.g. `$result->InsertVoucherResult` — to populate `raw_result` is **allowed protocol access**, not the forbidden extraction. What is forbidden is *business* parsing of that string: no splitting on `00`, no field/status/amount extraction, no status mapping. `raw_result` is the **single unredacted field** in the outcome: it is parser-bound functional data, must never be logged, displayed, or placed in an exception/diagnostic, and is exempt from the AC5 redactor (which governs the diagnostic fields only). [Source: epics.md:132 (raw SOAP/XML flows through redactor+parser before business logic); architecture.md:397,408,551]
8. **Conservative retry policy.** `BillPaymentInquiry` and `BillPaymentBulkInquiry` may be retried a bounded number of times on `timeout`/`transport_error` only. `InsertVoucher` is **never** auto-retried (idempotency unproven; a retried create can double-issue a payable voucher). [Source: epics.md:136; architecture.md:414; 0-1 contract: "Never auto-retry InsertVoucher"]
9. **Testable without live calls.** `SoapClient` creation is injectable so unit tests run with a fake/stub transport. Tests cover credential selection, redaction (flat + nested + raw-envelope), timeout→`timeout`, transport-failure→`transport_error`, SOAP-`<Fault>`-with-body→`ok=true`/`error_class=null`, InsertVoucher-never-retried, inquiry/bulk bounded-retry, and "no paid decision." No test calls a live KuickPay endpoint by default. [Source: epics.md:79 (FR28 client mapping + secret masking); NFR11 (no live calls; injectable seam for testability); architecture.md:477-483 (the `php -l` / no-root-PHPUnit verification stance only — not the injectability mandate)]
10. **No regressions to existing gateway behavior.** `buildProcess()`, `validate()`, `success()` remain fail-closed placeholders (no voucher creation, no transaction, no live SOAP). `encryptableFields()` still returns exactly `['voucher_password','inquiry_password']`. `editSettings()` validation, the same-as-voucher dedupe, the masked-credential indicators, and `maskCredentials()` are unchanged. `php -l` passes on every touched file. [Source: kuickpay.php:277-419; 1-1/1-3 non-negotiables]

## Dev Notes

### Scope boundary (read first)
This story delivers **transport only**: a reusable SOAP client wrapper + a redaction boundary. It explicitly does **not**:
- parse provider responses into normalized evidence (status/amount/error_class/etc.) → **Story 3.2** (`KuickPayResponseParser`, `KuickPayEvidence`);
- create/reuse vouchers, compute reference/consumer numbers, or map invoices → **Epic 2** (2.1-2.3);
- create or apply any Blesta transaction or mark anything paid → **Story 3.5** (`KuickPayPostingService` is the only class allowed to post);
- persist durable Voucher/audit/reconciliation state → **plugin** (`kuickpay_reconcile`).
The single most important invariant: **the client returns transport facts and the raw payload; it never decides payment meaning.** [Source: architecture.md:397,569-579,581-583,665-671]

### Architecture compliance (guardrails)
- **One SOAP home.** External KuickPay SOAP calls live only in `KuickPaySoapClient.php`. No controller/view/cron/posting/reconciliation service — and not `kuickpay.php` itself — may `new SoapClient` or branch on raw SOAP/XML. The gateway's only SOAP-related code is the `getSoapClient()` factory. [Source: architecture.md:383-406,770-772,648-661]
- **Flow:** `SOAP client -> redactor -> parser -> normalized result -> state machine`. This story owns the first two arrows; the parser onward is later stories. [Source: architecture.md:397]
- **Fail closed.** Unknown/ambiguous transport states are surfaced as `transport_error`/`timeout`, never as success. Business "unknown/malformed/duplicate" mapping is the parser's, and those always fail closed to retry/Manual Review, never paid. [Source: architecture.md:569-579; NFR9]
- **Amounts:** this story does not compare amounts; if you ever surface an amount in a diagnostic, keep it a string — never cast provider numbers to PHP float. [Source: NFR13; architecture.md:593]
- **Anti-patterns to avoid:** creating a transaction in any gateway path; parsing SOAP XML for business meaning here; storing raw SOAP/credentials in logs; hard-coding endpoint/institution/credentials. [Source: architecture.md:648-661]

### PHP 8.2 `SoapClient` specifics (built-in, no new dependency)
`ext-soap` is required for this story — confirm it loads (`php -m | grep -i soap`); it is not in the project-context required-extensions list, so flag if missing. Key options:
- `connection_timeout` (int) bounds the connect phase. There is no built-in read-timeout option, so also bound `default_socket_timeout` (set/restore via `ini_set` around the call) and put a `timeout` in the stream context.
- `stream_context` (from `stream_context_create`) carries TLS opts: `ssl => verify_peer=true, verify_peer_name=true, allow_self_signed=false`. The WSDL is fetched over this same context — TLS verification applies to WSDL load too.
- `exceptions => true` makes faults throw `SoapFault` (catch it); `trace => true` enables `__getLastRequest()`/`__getLastResponse()` for redacted diagnostics.
- `cache_wsdl => WSDL_CACHE_MEMORY` avoids re-fetching the WSDL each call within a process while staying correct.
- ASMX services work in WSDL mode; pass operation params as one associative array to `__soapCall($op, [$params])`.

### Redaction details
`maskDataRecursive()` (gateway.php:342-363) is array-keyed and recursive, but it **delegates the actual masking to the private `maskValue()` (gateway.php:379-404)** — that is where the length-preserving `str_repeat($mask, strlen($value))` default lives (line 400). Port **both** routines into `KuickPayRedactor::redactArray()` (the redactor is standalone, not a `Gateway` subclass); porting only the recursion leaves a call to a non-existent `maskValue()`. Cast non-string scalar leaves to string before masking and pass `null` through untouched (PHP 8.2 deprecates `strlen(null)`). For raw envelope strings use `DOMDocument` **matching sensitive elements by local name** (the provider uses a default namespace — see fixture — so prefixed `getElementsByTagName()` matches nothing) with DOCTYPE rejected and `LIBXML_NONET`; do **not** call the deprecated `libxml_disable_entity_loader()` (external entities are already off by default in PHP 8.2). Replace sensitive element text with a fixed token; on any parse failure return a constant placeholder, never the raw XML. Redact BEFORE anything is logged, returned as a diagnostic, or placed in an exception message — every time. (`raw_result` is the sole exception: it is functional parser input, never logged/shown — AC7.) [Source: 1-3 non-negotiables; architecture.md:373,656; NFR8]
